# From Plan to Practice: Simulating Schedule Overrides

Simulation code for my Bachelor End Project (1BEPIE, Industrial Engineering, TU/e):
*From Plan to Practice: Simulating Schedule Overrides and Task Completion for Automated Personal Scheduling*.

The simulation reads a planned calendar (iCalendar `.ics`) generated by [calendar-bench](https://github.com/MaaniBeigy/calendar-bench), generates override events that depend on the persona, notifications, the calendar state and the simulation parameters, updates the plan accordingly, and returns the calendar as it was actually executed.

## Current status (version 1)

`src/simulation.py` runs an event-driven override simulation:

1. **Load** the planned calendar and split it into planned tasks and `[ctx:...]` context annotations (the context is kept for version 2).
2. **Arrivals:** a Poisson process (default λ = 0.4 per hour) generates override events over the experiment horizon.
3. **Active task:** each arrival looks at the *executed* calendar at that moment. Arrivals in free time, during sleep, or during an excluded task (sleep, meals, meetings, ...) are ignored.
4. **Decision:** a multinomial logit gives the probabilities of *no override*, *postpone*, *skip* and *replace* from the planned hours left in the day, the number of earlier overrides today (which lowers the chance) and whether the task was notified.
5. **Update:** postponed tasks move to the next free slot on the same day that respects the calendar-bench temporal rules (otherwise they are skipped), skipped tasks are cut off, replaced tasks become an `UNPLANNED` block of the same length.
6. **Replications:** R runs (default 30) with confidence intervals on the KPIs: completion rate, shares postponed/skipped/replaced, mean postponement delay, plan–execution deviation.
7. **Output:** the executed calendar as `.ics` plus an Excel workbook with the KPI summary, every change, and the details per task.

Parameters, including a parameter set per persona, are in [`config/override_config.yaml`](config/override_config.yaml). All probabilities and coefficients there are **assumptions for version 1**, not fitted values.

Not yet in version 1: task context and persona characteristics as inputs of the probability, scenario (health) tasks from calendar-bench, and replacing with a specific activity.

## Installation

Requires Python 3.9+.

```bash
pip install -r requirements.txt
```

## Usage

```bash
python src/simulation.py path/to/calendar.ics
python src/simulation.py path/to/calendar.ics --replications 5
python src/simulation.py path/to/calendar.ics --config path/to/override_config.yaml
```

Without a calendar argument, the script uses `DEFAULT_ICS_FILE` at the top of `simulation.py`. Without `--config`, it uses `config/override_config.yaml`.

Output, next to the `.ics` file (or in `output.dir` of the config):

- `<calendar>_override_simulation.xlsx`: KPI summary, replications, changes, decisions, tasks, executed calendar, parameters.
- `<calendar>_executed_run1.ics`: the executed calendar of replication 1, to compare with the plan.
